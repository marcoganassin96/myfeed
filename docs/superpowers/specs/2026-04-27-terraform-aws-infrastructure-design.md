# Terraform AWS Infrastructure Design

**Date:** 2026-04-27
**Scope:** Provision pre-requisite AWS infrastructure for the newsletter API serving layer (Phase 1 load testing gate)
**Feeds into:** `sam deploy` parameters in `infra/template.yaml`

---

## Goal

Provision VPC, Aurora Serverless v2 + RDS Proxy, and ElastiCache Serverless (Redis) using Terraform so that `sam deploy` can deploy Lambda functions into a fully wired AWS environment. Load tests (k6) run against the resulting API Gateway URL.

---

## Architecture

Three independent Terraform modules called from a single environment root. Outputs wire directly into SAM parameters via `scripts/deploy.sh`.

```
terraform/
  bootstrap/            # one-time: S3 bucket + DynamoDB lock table
    main.tf
    outputs.tf
  modules/
    vpc/                # VPC, subnets, NAT GW, security groups
      main.tf
      variables.tf
      outputs.tf
    aurora/             # Aurora Serverless v2, RDS Proxy, Secrets Manager
      main.tf
      variables.tf
      outputs.tf
    redis/              # ElastiCache Serverless
      main.tf
      variables.tf
      outputs.tf
  envs/
    dev/                # dev environment root
      backend.tf        # S3 backend config
      main.tf           # calls all 3 modules
      variables.tf
      outputs.tf        # VpcId, SubnetIds, DbHost, RedisHost, DbPassword
      terraform.tfvars  # dev values (gitignored)
scripts/
  deploy.sh             # reads TF outputs → sam deploy
```

**Region:** `eu-west-1` (matches `samconfig.toml`)
**Availability zones:** `eu-west-1a`, `eu-west-1b`

---

## Module: vpc

**Purpose:** Network foundation for all other resources and Lambda functions.

| Resource | Detail |
|---|---|
| VPC | CIDR `10.0.0.0/16` |
| Private subnets | `10.0.1.0/24` (eu-west-1a), `10.0.2.0/24` (eu-west-1b) — Lambda, Aurora, Redis |
| Public subnets | `10.0.101.0/24` (eu-west-1a), `10.0.102.0/24` (eu-west-1b) — NAT GW only |
| NAT Gateway | Single instance in eu-west-1a (cost-optimised for dev) |
| Internet Gateway | Attached to VPC for public subnet egress |
| Security group: `lambda_sg` | Egress all; no ingress |
| Security group: `aurora_sg` | Ingress 5432 from `lambda_sg` only |
| Security group: `redis_sg` | Ingress 6379 from `lambda_sg` only |

**Outputs:** `vpc_id`, `private_subnet_ids` (list), `private_subnet_ids_csv` (comma-joined for SAM), `lambda_sg_id`, `aurora_sg_id`, `redis_sg_id`

---

## Module: aurora

**Purpose:** PostgreSQL database with connection pooling for Lambda fan-out.

| Resource | Detail |
|---|---|
| Aurora Serverless v2 | PostgreSQL 15, min 0.5 ACU → max 16 ACU |
| DB cluster | Multi-AZ writer in private subnets |
| Password | Generated by `random_password`, stored in Secrets Manager |
| RDS Proxy | Password auth (IAM auth disabled for Phase 1 simplicity) |
| Subnet group | Private subnets from vpc module |
| Security group | `aurora_sg` from vpc module |

Scales to near-zero when idle — cost-safe for dev. RDS Proxy mandatory: Lambda cold starts produce connection storms without it.

**Outputs:** `rds_proxy_endpoint`, `db_name`, `db_user`, `secret_arn`, `db_password` (sensitive)

---

## Module: redis

**Purpose:** ElastiCache Serverless Redis cluster for 1h newsletter cache.

| Resource | Detail |
|---|---|
| ElastiCache Serverless | No node sizing; AWS manages capacity |
| TLS | Enabled (`REDIS_SSL=true` in SAM globals) |
| Auth token | None (VPC security group is the access boundary for dev) |
| Subnet group | Private subnets from vpc module |
| Security group | `redis_sg` from vpc module |

**Outputs:** `redis_endpoint`, `redis_port`

---

## State Backend

**Bootstrap** (`terraform/bootstrap/`) provisions:
- S3 bucket: `newsletter-tfstate-<aws_account_id>` — versioning enabled, AES256 encryption, public access fully blocked
- DynamoDB table: `newsletter-tfstate-lock` — PAY_PER_REQUEST billing, `LockID` hash key

Bootstrap state is intentionally **local** — cannot store state in a bucket that does not exist yet. Bootstrap files are committed to git (no secrets).

`terraform/envs/dev/backend.tf` references the S3 bucket/table created by bootstrap.

---

## SAM Integration

`envs/dev/outputs.tf` maps to SAM parameters:

| Terraform output | SAM parameter |
|---|---|
| `vpc_id` | `VpcId` |
| `private_subnet_ids_csv` | `SubnetIds` |
| `rds_proxy_endpoint` | `DbHost` |
| `redis_endpoint` | `RedisHost` |
| `db_password` | `DbPassword` |

`scripts/deploy.sh` reads these outputs and calls `sam deploy` — no manual copy-paste.

---

## Secrets

- DB password: Terraform `random_password` resource → AWS Secrets Manager → Terraform output (marked sensitive)
- `terraform.tfvars` is gitignored
- No secrets in committed files

---

## Deployment Sequence

```bash
# 1. Bootstrap (once per account)
cd terraform/bootstrap && terraform init && terraform apply

# 2. Init dev environment (once, after bootstrap)
cd terraform/envs/dev && terraform init

# 3. Provision infrastructure (~10 min)
terraform apply

# 4. Deploy Lambda + API Gateway
cd ../../.. && ./scripts/deploy.sh

# 5. Seed data
python scripts/seed.py  # targets live Aurora via env vars

# 6. Create Cognito test tokens
python scripts/create_test_tokens.py

# 7. Run k6 load tests
k6 run -e API_URL=... -e COGNITO_TOKEN=... load_tests/mixed_realistic.js
```

---

## Adding prod Later

Create `terraform/envs/prod/` mirroring `envs/dev/` with production-grade values (higher Aurora ACU, multi-AZ NAT GW, stricter SGs). Modules are reused unchanged.
